# ADR-0001: Foundation data model

**Status:** accepted in Milestone 0a.

The canonical primitive is `entity + claim + relationship + evidence + time`. A relationship is a claim whose typed value is another entity. `entities` retains only identity, a small typed core, place extension data, and derived cache columns. Substantive facts live in `claims`, whose predicate must be defined in the checked-in domain registry. Values use typed columns (text, number/unit/range, enum, entity, or date), never a JSON value blob.

Claims are temporal records. A current public read sees only `APPROVED` claims with an open validity range; an `as_of` read resolves the historical range. Replacing a fact closes and marks the previous row `SUPERSEDED`, then inserts a replacement; history is not overwritten. Cache columns are recomputed from those current approved claims and are filtering/sorting aids only.

Evidence is a separate many-to-one record with ordinal class and confidence. A sourced approved claim needs evidence; corroborating and conflicting evidence coexist. `ANALYST` evidence is structurally different: its rationale, criteria, considered claims, reviewer, and review date live in `assessments`, keyed by evidence id. `DERIVED` evidence must point to input claims through `claim_dependencies`. Sources have one canonical identity table in 0a; 0b extends that table rather than replacing it.

PostgreSQL 16 is the canonical store. Drizzle owns the schema and visible SQL migrations; Zod owns public contract validation and TypeScript types are inferred from it. The graph is projected from relational claims at read time. We do not use a graph database because relationship predicates are bounded and typed, temporal/evidence joins are central, and Postgres provides transactional integrity, ordinary filters, and full-text/trigram search without a second source of truth.

Fixtures are generated by invoking the same read handlers against the seeded database, then parsing every response with its route schema. Frontends receive a `DataProvider` and are unaware whether its values came from fixture JSON or HTTP. This prevents fixture drift from the public contract.
